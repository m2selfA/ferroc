## Parallel pure manifest/diff track — NOT P0 sign-off or P2 apply

The original transfer plan explicitly permits pure manifest/diff tests alongside blocked P0 review. `manifest.rs` validates logical canonical relative UTF8 entries with hard caps:100000 entries,4096 bytes/path,16MiB total path bytes,128components,64GiB/file. Root is implicit; all other ancestors require Directory entries. Validation is after caller allocations, not a parser/network allocation guarantee. This is metadata, not a coherent scan or verified file digest. ExactUtf8Unqualified never case-folds or Unicode-normalizes keys and NEVER proves native target name/object distinction. Later native qualification must detect case/alias/normalization collisions, re-observe and authorize; do not blindly execute these descriptions.

Checksum is default. Equal metadata but unequal SHA selects a whole-file change; missing needed digest returns error, not quick fallback or a partial executable plan. Quick is explicitly heuristic and uses size inequality OR any mtime inequality, including backdated source; equal metadata can still hide changed content. Source copies in checksum mode require source SHA; equal-size target comparisons require target SHA, but extra/size-mismatched targets need no useless hashing. Same digest with different size still selects change. All inputs remain untrusted caller claims until actual later IO.

Diff output is immutable descriptive dry-run, sorted deterministically with parents first. Empty dirs get EnsureDirectory. Source-directory/target-file conflict blocks descendants by COMPONENT prefix, not string prefix; source-file/target-directory conflict preserves the target subtree. Every target-only entry remains RetainedTarget, never a delete. CopyWholeFile/ExistingFile says what differs, NOT an overwrite grant; current v9 no-clobber publication cannot simply apply a changed-existing-file plan. file_bytes_selected is selected logical size, not traffic/encoded/received/committed progress. No scan, symlink handling, exclusions, transport, apply or delete API, durable plan import, or P2 acceptance is implied.

## Candidate peer-record bytes

All integers are unsigned big-endian. One record occupies exactly one future fleet binary WS message; **do not parse this on legacy BRC `/ws`**. The 216-byte header is AES-GCM AAD. The following body is `plaintextLen` encrypted bytes plus a 16-byte tag. Frame parser borrows ciphertext and rejects invalid lengths before allocation. Transport-level WS message/frame caps must be installed in P1; a bounded parser is not a network allocation bound.

| Offset | Bytes | Field |
|---|---:|---|
| 0 | 8 | ASCII `FRCFL001` |
| 8 | 2 | version 1 |
| 10 | 1 | kind: PREPARE=1, READY=2, DATA=3, ACK=4, FINISH=5, COMMIT_ACK=6, CANCEL=7, STATUS_REQUEST=8, STATUS=9 |
| 11 | 1 | direction: source→target 0, target→source 1 |
| 12 | 2 | reserved flags, must be zero |
| 14 | 2 | header length, exactly 216 |
| 16 | 4 | encrypted body length including tag |
| 20 | 176 | binding below |
| 196 | 8 | sequence, starts 0, below 2^20 per direction/key |
| 204 | 8 | file offset; zero except DATA |
| 212 | 4 | plaintext length |

Binding order: fleet UUID (16), source device digest (32), target device digest (32), source session UUID, target session UUID, transfer UUID, file UUID, authorization UUID, key epoch UUID (each 16). UUIDs must be non-nil; device digests must be nonzero/distinct. Device digest is SHA-256 of `ferroc:fleet:device-id:v1\0 || u16(UTF8 length) || exact opaque device-id bytes`. This does not invent UUID device IDs or multi-user ACLs.

DATA is 1..262144 bytes, and checked `offset+length <=64 GiB`. Control payload is at most 16384 bytes and has strict typed schemas with job/grant digests (below). This is not coordinator ACL integration, message ordering, a running transfer handler or transport allocation protection. READY/ACK/COMMIT_ACK/STATUS are target→source; the other kinds are source→target. Therefore receiver-originated errors/cancellation must be represented in a future typed STATUS schema; raw kind codes alone do not implement tool semantics.

No parser accepts reserved versions/kinds/flags, trailing bytes, overflows, empty DATA, wrong directions or nil binding IDs. These are bounded framing primitives, not a claim of full fleet/1 wire interoperability.

## Identity and AEAD

Externally approved Ed25519 pins bind exact source/target device IDs to public keys. `DevicePin::approved` is an explicit trusted-caller boundary, **not proof of human approval, enrollment or disk persistence**. Never construct expected pins by copying an unverified offered transcript. No AcceptAny/automatic TOFU fallback exists here. Initial relay trust and operator fingerprint verification are still enrollment work, not something inferred from successful DH.

Both peers now sign **420 bytes**: `ferroc:fleet:auth:v2\0 || u16(suite=2) || roleByte || binding || jobDigest[32] || grantDigest[32] || sourceEd25519 || targetEd25519 || sourceX25519 || targetX25519 || u64(fileBytes) || u32(chunkBytes) || u64(issuedAtMs) || u64(expiresAtMs)`. The role byte prevents reflected signatures. An ephemeral private key is consumed, cannot be cloned/reset/imported through production APIs, and must match its role. The full locally expected structurally validated grant must match before signatures/DH; even two genuine peer signatures cannot replace its job/constraints. Both signatures, locally expected binding and external pins must verify before contributory X25519 DH. Empty files allow fileBytes=0 but cannot send DATA. Suite-1 signatures have no automatic downgrade path; historical vectors remain oracle-only.

Authenticated root: HKDF-SHA256(shared DH, salt=SHA256(source-role transcript), info=`ferroc:fleet:authenticated-root:v2`, len=32). Record key: HKDF-SHA256(root, salt=`ferroc:fleet:hkdf-salt:v1`, info=`ferroc:fleet:record-key:v1\0 || binding || directionByte`, len=32). Nonce: four zero bytes plus u64 sequence. The entire header is AAD. Bare-root sealer/opener constructors are crate-private; no production API exposes deterministic fixture seed import.

Sequence is burned before encryption. Retransmission must reuse saved ciphertext bytes, not reseal changed content. Receiver holds exactly 128 replay slots; authenticated identical ciphertext returns Duplicate without plaintext/rewrite/progress. Conflicting nonce/sequence, stale window and wrong binding fail. An unauthenticated high sequence never advances the window. Production queues, ACK caching, control priority and rate limiting remain P1 work.

Secret roots/derived key buffers and decrypted plaintext use Zeroizing. This is **not a guarantee that ring's internal key representation, allocator copies or kernel buffers are wiped**. Candidate protected identity/pin storage and native Windows owner/DACL checks now exist in `identity.rs`, `identity_protection.rs` and `identity_windows.rs`. Complete secret-lifecycle audit, platform qualification and operational human enrollment remain pending.

## Stable jobs, scoped grants and typed controls (candidate control-v2)

`JobSpec` fixes fleet/source/target, transfer/file UUIDs, exact source/destination path bytes, length, expected SHA-256, no-clobber flag, relay-only route, a fixed total deadline and idempotency key. Source prehash is required by this candidate; final readback must match that authorized SHA. Paths are 1..4096 UTF-8 bytes, rooted Unix or Windows disk files, without control characters/dot traversal/ADS or the stage namespace. UNC/device/extended namespaces are explicitly unsupported in this candidate; each endpoint must still resolve its actual local Policy. No cross-platform sandbox equivalence is claimed.

Canonical bytes use distinct request/job/grant domain prefixes and big-endian integers/u16 UTF-8 byte lengths. Request digest excludes coordinator-assigned transfer/file UUIDs and the idempotency lookup key. Job digest adds those stable UUIDs and key. Grant digest adds the entire session/key binding, job digest, SendFileNoClobber permission, exact chunk limit and issued/expiry times. Session/epoch/authorization rotation changes the grant but not the job digest. Structural `ValidatedGrant` has no Deserialize/unchecked constructor, but is **not proof of a trusted issuer, human consent or local path approval**. The future coordinator/endpoint must supply that trust independently; no peer-offered grant creates it.

`IdempotencyLedger` is a 1..128-entry **in-memory** component scoped to one trusted coordinator authority. Same fleet/key and exact request digest returns the first accepted stable IDs, even when a retry generates fresh IDs or arrives after the deadline. Changed parameters are a conflict, not replacement; a full ledger rejects new work and never evicts unresolved jobs. It has no persistent replay protection, eviction/recovery policy or multi-user ACL claim.

All controls use strict bounded JSON: `{version:1, jobDigest, grantDigest, body:{type,payload}}`. Every struct and the adjacent tag reject unknown/duplicate fields; unknown enum values, oversized/truncated/trailing input, wrong header kind/binding and wrong digests fail. Payloads have no arbitrary error strings or peer paths.

| Kind | Payload constraint |
|---|---|
| PREPARE / STATUS_REQUEST | Empty object; existing locally expected job/grant mandatory |
| READY | Exact grant chunk limit, 1..8 receive window |
| ACK | Contiguous <= received <= total; out-of-order bytes <= eight granted chunks; no commit claim |
| FINISH | Exact authorized size and SHA |
| COMMIT_ACK | Non-nil stable receipt UUID, exact size/SHA, parent durability explicitly Synced or Unsupported |
| CANCEL | Closed reason enum; source-to-target only |
| STATUS | Separate received/committed counts; Completed needs matching receipt/full counts/no cleanup debt; Cancelled needs confirmed cleanup; CommitUnknown cannot claim committed bytes |

Public `LeasedRecords` exposes `seal_data`, `seal_control`, `open_record` without a supplied timestamp. Raw `AuthenticatedRecords` and its logical-time constructor are crate-private; arbitrary control seal/open remain crate-private. An authenticated but semantically invalid control faults the key session, so retry cannot become a falsely acceptable Duplicate. AEAD corruption alone does not poison valid processing. This is **not a lifecycle controller**: PREPARE/READY ordering, cancellation admission and persisted receipt truth must be enforced by the future coordinator. A syntactically valid receipt does not prove file IO or durability.

## Cooperative native owner fence and same-database connection ownership

`fence.rs` adds `OwnerFence::acquire(existing_db)` → `open_connection()` → `FencedConnection::journal()`. Native `File::try_lock` is nonblocking; contention and unsupported OS/filesystem errors fail closed. It locks an empty fixed sidecar derived from the database's actual single-link file identity, never SQLite's own byte locks or a long-lived SQL transaction. Cooperating code must never unlink, replace or truncate that marker. A failed first acquisition may leave the empty marker, not a new DB/schema. There is no PID/heartbeat/clock death inference or automatic permission repair.

The existing DB and actual parent must already be private/trusted; Windows validates current-user owner/DACL and no final-component reparse, Unix checks exact0600/0700 owner/nofollow. File hardlinks are refused for both DB and marker. Parent aliases are canonicalized to the same actual database/marker; a genuine Windows junction alias is tested. Windows handles exclude delete sharing and native rename denial is tested. This is cooperative local ownership, not protection against a malicious same-user ancestor/path mutation, non-cooperating SQL clients, or a distributed/network-filesystem fence.

A private `Arc<FenceDomain>` keeps the lock alive across all opened connections after the non-cloneable factory drops. Each SQLite connection is dropped before its retained guard; only the final guard release closes the OS lock. This is usable in long-lived host state without a self-referential borrowed connection or a new service/database. No raw connection or lock handle is exported. Existing relay code must adopt the fenced opening order for the SAME database; a filename from an arbitrary pre-existing SQLite connection is not proof of its underlying file identity. No operational relay integration is claimed yet.

Normal `Journal` attachment is only reachable from that guarded factory; bare `attach` and raw `into_connection` are cfg(test) historical fixture adapters. Schema attachment, every public read, shared mutation helper, admission and stopped-owner recovery recheck the current domain/paths. Old owner recovery while newly holding the same cooperative exclusive fence preserves prior conservative semantics: real intent → CommitUnknown, retains stage reference/bytes, no automatic resume/delete or receipt invention. This does not reconstruct orphan quota or make DB+filesystem commit atomic.

Windows native tests cover exact WouldBlock across processes, graceful/unclean/forced exit release, retained connections after factory drop, real intent crash with surviving actual stage, DB/memory domain mismatch, hardlinks, path spelling/junction aliases, pinned rename denial, actual marker size mutation and pre-schema rejection. DB/marker/parent ACL widening is exercised through the existing helper with original descriptor restoration. Normal API has a positive compile gate as well as negative gates forbidding factory clone, raw connection export and unfenced journal entry. Unix source/mode test exists but has not run: local WSL reports not installed, no Docker/Podman or GNU Linux Rust target. Rustc here is1.98.1; std try_lock stabilized1.89 per the saved primary documentation, not a declared project MSRV or verified GNU ABI claim.

## Cancellation-aware stage readback and native publication admission

`StageFile::verify_with(expected_sha, check)` checks a trusted local observer before/after each at-most64KiB read and after file sync; actual size/SHA/coverage are validated. A cancelled/expired/IO/hash failure returns `StageRejected<StageFile>` holding original bytes/reservation. It does not interrupt an already blocked OS read/sync syscall. Readback is not automatically resumed from journal counters.

`VerifiedStage` owns the original stage privately and exposes no write API; it is a readback observation, not a reusable authorization. `publish_with(admit)` now delegates to `publish_checked(check, admit)`: under the same real Runtime fs_gate it rechecks size/policy, compares the retained File and current path by native object identity, rehashes actual bytes and syncs, rechecks identity and target absence, then invokes trusted LOCAL admission exactly once. Final hash checks bracket each64KiB read and post-sync; these callbacks must NOT acquire DB or reenter fs_gate. Holding this gate excludes cooperative Runtime writes through publication, not hostile same-user external IO. Caller must bind job/owner/revision, establish fencing and check lease again after any durable SQL/fsync work before returning success. Callback must not reenter fs_gate or invert lock order. No native fence or receiver coordinator is implied by this callback API.

Pre-admission failures return `StageRejected<VerifiedStage>` with ownership/quota retained. Do not discard that error after a durable intent: dropping it still invokes best-effort StageFile cleanup and is not a cancellation acknowledgement. After native no-clobber attempt, outcome remains Published/Uncertain, never a safe-to-retry error. GuardedTempFile rechecks native object identity at actual Drop time, using only try_lock on the real Runtime gate. A busy gate, missing/unreadable/replaced path or prior identity loss disables tempfile cleanup and permanently quarantines the component budget. Drop never waits/reenters the gate; shared atomic loss state reaches the later Reservation destructor even after the stage path disappears. Explicit close/persist consume the guarded file only from their existing gated call sites. Detected ownership loss rejects explicit cancel/republication even after restoring the original path. The original file may have moved elsewhere; absence alone cannot release that charge. Explicit owned-object cleanup may drain a poisoned gate without clearing its poison, but still requires matching object identity. This is not persistent host recovery or an OS sandbox guarantee. Parent durability remains platform-qualified.

Legacy unchecked `publish` is cfg(test) only, for historical fixtures/scale. Compile-fail gates prove non-test callers cannot use it or write to VerifiedStage. New tests cover bounded read cancellation/reverify, SHA failure ownership, zero-byte post-sync cancellation, real fs_gate handoff and poisoning, final callback rejection, target collision/no-clobber uncertainty and post-read size changes. Real LeasedRecords revocation rejects publication; expiry test uses an explicit synthetic clock with actual file IO, not native wall-clock sleep equivalence. A real SQLite+Stage test deterministically exercises both cancellation-before-intent and intent-before-cancellation against real native publication/receipt. It is still single-machine component validation, not receiver/network/OS power-loss acceptance.

## Durable pre-creation obligations and empty-file binding (candidate)

`FencedConnection::reserve_stage` validates the existing queued job/revision/owner, local transfer policy, private canonical parent and bounded read-only inventory under the caller's actual fs_gate. Any existing stage debt or unresolved scope blocks this conservative one-at-a-time candidate, even with a fresh quota object. The same SQLite IMMEDIATE/CAS transaction records a UUID stage path, full authorized bytes, origin owner, stage-parent object ID, actual DB object ID and DB-parent object ID, sets the row to **Interrupted/isolation** with zero received bytes, and atomically raises fleet metadata to version3. It creates no data file. Version1 rows and table names are retained; merely opening a database does not upgrade it. Older implementations reject metadata3; historical metadata2 obligations lack persisted DB-domain evidence and are never silently backfilled or granted creation/release authority; there is no downgrade/fallback or added database/service.

`create_reserved_stage` reloads the still-current origin owner's isolated unbound reservation. It rechecks policy/destination absence/canonical parent ID, uses the existing private native CREATE_NEW mechanism, syncs the empty file, observes its object ID and parent again, then CAS-persists that binding. It returns a metadata Snapshot, NEVER a File, StageFile, receiver permission or range coverage. Ordinary File drop only closes; any filesystem/sync/SQL/CAS error leaves the obligation and any created file quarantined. Existing files are never adopted, truncated or deleted. A commit error can be indeterminate: inspect/reconcile, do not retry creation blindly. Concurrent cancel may leave an empty stage; it cannot erase the recorded obligation or claim cancellation complete. No long filesystem read/write is performed inside the metadata write transaction.

Legacy attach rejects supplied allocation metadata. Legacy path-absence `confirm_removed` rejects allocated obligations even when absent. Cancellation and stopped-owner recovery retain them; changing journal owner does not replace allocation origin owner, so takeover cannot replay an old create request. The explicit LOCAL absent-path reconciliation contract below can retire a stopped-origin, same-domain obligation; existing objects still require a future authenticated cleanup/coordinator contract. This is not the full host admission coordinator, and unrelated historical StageBudget/StageFile primitives remain outside this metadata factory.

Inventory charges pre-created reservations too: unbound/missing records remain hard unresolved findings, not zero debt. A bound observation only records equality of current file/parent IDs to saved IDs; a mismatch blocks the budget. This is not cryptographic ownership, content verification, protection against inode/file-ID reuse, malicious same-user actors/non-cooperating SQL writers or cross-filesystem object-ID portability. Legacy identity remains explicitly unproven. Windows reports parent durability Unsupported; file sync plus SQLite FULL is NOT proof of atomic filesystem+DB commit or power-cut survival. No writable receive/resume/automatic deletion is added; P1 stays blocked.

## Time, quotas and coverage

Task deadline and authorization lease remain distinct. `lease.rs` now provides a process-local `LeasedRecords` facade; raw `AuthenticatedRecords` and `EphemeralKey::authenticate(..., u64 now)` are crate-private. Public mutation/control/receive APIs sample local time themselves, not peer-provided epoch timestamps. Signed metadata remains suite2/420 bytes; both frozen Node oracles are unchanged.

`TrustedTimeAnchor::approved_window` is an explicit **trusted-caller** boundary: its earliest/latest values must bound authority time at the supplied local `ClockSample`, accounting for source uncertainty, transport latency and drift. No network clock provider, clock synchronization claim or zero-skew default is implemented. Import requires the whole interval to be inside the granted lease. Local samples have private fields/no Deserialize. Rustdoc compile-fail gates check external code cannot construct raw sessions or forged samples.

The anchor is imported once. Later lower time uses the smaller floored Instant/SystemTime elapsed value, upper time the larger rounded-up value; expiry checks use the conservative upper bound. Fixed job and lease Instant cutoffs additionally prevent expiry extension. Record encrypt/decrypt/control decoding also sample time again before returning: processing that crosses expiry cannot expose DATA/FINISH effects. Burned nonces are never rolled back; read-only settlement remains allowed with valid clock continuity. This tightens record delivery but still does not replace the real filesystem admission guard. Local monotonic or wall-clock rollback, arithmetic overflow, or accumulated elapsed-clock divergence above **2000ms** irreversibly poisons continuity for this instance. This conservative fence can stop a job after an NTP/manual step; it never relaxes tolerance or re-anchors automatically. Actual OS clock step/suspend behavior has not been live-qualified; injected samples test the decision logic. The fence detects observable disagreement, not simultaneous unobservable stalling of both clocks or a compromised host. It does not certify real UTC elapsed time or a hypervisor/OS suspend route; production trusted-time validation and native qualification remain required. No host clock or registry is changed by the tests.

Renewal is a local authenticated-handshake primitive, **not a running wire renewal endpoint**. It must complete before the old lease expires, while the original fixed job deadline is live. It requires identical stable job digest/permission/live source+target sessions, no chunk-ceiling expansion, increasing signed issue and expiry values, entirely live new interval, unused authorization/key epoch IDs and fresh distinct X25519 public material. Original identity pins and role remain fixed. Both signatures/private-role match must pass and time is checked again after crypto before atomic install. Failure consumes elapsed time but never replaces keys, resets the active sequence or burns a new epoch slot. A narrowed ceiling cannot be restored by later renewal. Revocation permanently blocks new effects/renewal on this instance.

History retains at most **1024** epoch authorization IDs/key epoch IDs and twice as many public ephemeral keys; no eviction/reacceptance or old private epoch keys. This is process-local bounded history, not crash-persistent replay protection. New epoch keys may restart sequence0 only with a fresh signed key context; stage bytes/coverage/reservation are external and must not reset. Old epoch records are rejected after replacement. Late already-committed receipts must be authenticated again in the current context and reconciled with the future durable journal; dropping an old receipt never proves rollback/cancellation.

After ordinary lease expiry or revocation, the still-active epoch may settle ACK/status/cancel/receipts, but cannot PREPARE/READY/DATA/FINISH or renew. Clock continuity failure closes even settlement on that instance; recovery needs a separately authenticated journal/reconciliation path, not a forged clock reset. `check_commit_admission` only checks **at** the caller's real commit boundary; it is not a reusable permit and does not split StageFile readback/publication or hold fs_gate. The cancellation-aware split now exists in StageFile/VerifiedStage; its observer is still trusted LOCAL code, not a running authenticated receiver or a reusable lease permit.


File hard ceiling: 64 GiB. Receive metadata holds at most 8 out-of-order ranges within a 2 MiB span; filling the contiguous hole remains possible when the window is full. Overlap, conflicting duplicate, overflow and premature completion fail. Receiver validates before IO and records coverage after successful write. A repeated ciphertext must be intercepted by the replay opener; old data below the contiguous prefix is not rewritten. Whole-file final SHA, not per-chunk digest, is the completion criterion.

StageBudget bounds aggregate logically reserved bytes and at most four active stages, including zero-length files. A stage path is attached to its reservation. Tempfile cleanup runs before reservation finalization; only confirmed path absence releases bytes and the active slot. Failed/unreadable cleanup and residual hardlinks retain both charges in a local bounded registry (at most max_active entries). `retained()` reports them without deleting, and `reconcile_removed()` releases only registered paths now confirmed absent; unblocking a handle alone does not release anything. The caller must verify ownership before removing a residual. Read-only reconciliation does not perform deletion or accept peer-selected paths. It is **not physical free-space reservation**, restart orphan accounting, a persistent coordinator quota or OS-sandbox protection against same-user path replacement.

## File and job transaction boundaries (historical StageFile/model, not Host v9)

StageFile requires an existing destination parent, transfers enabled, and local Policy resolution. It never mkdirs or overwrites. Reserved `.ferroc-fleet-` names (case-insensitive check) cannot be final destinations. Stage is independently/exclusively created in the target directory. Writes and SHA reads use bounded buffers. Any IO or validation failure faults the stage; a partial write never advances byte coverage or permits later publication.

Publication requires complete coverage, actual bounded file readback with matching length and SHA, file `sync_all`, and final Policy/path/absence check under the caller's actual Runtime fs_gate. Network wait/file hashing must not hold that gate. Existing same-user filesystem races are outside Policy's sandbox claim; no OS handle-relative no-follow sandbox has been implemented.

`tempfile::persist_noclobber` guarantees no overwrite, but its 3.27.0 source warns overall operation can leave the old temporary hardlink. Publication errors, unconfirmed old-link cleanup or Unix parent sync failures return Uncertain once publication has been attempted. Windows parent directory sync is explicitly Unsupported. Published is **not a durable protocol receipt, atomic DB transaction or completed remote task**. This historical StageFile component alone does not integrate journal/orphan ownership. Later Host inventory, reconciliation and v9 settlement components described above add those local contracts; their existence is not production integration or independent sign-off.

Explicit `cancel()` closes/removes the owned stage and returns cleanup errors with the residual local path. Drop is best-effort fallback, not cancellation confirmation. Both preserve quota if the path still exists or its absence cannot be confirmed; SHA/readback failure and publication-error paths follow the same rule. Publication may be uncertain even when the old stage path is absent: freeing its stage charge never resolves commit/journal uncertainty. The state model requires cleanup confirmation before Cancelled. After commit admission, disconnect/cancel/deadline produces CommitUnknown, never a false rollback. Matching, authenticated, durably persisted receiver receipt is the trusted input required for Completed; late matching receipts may settle uncertainty, and duplicate identical receipts are idempotent. The model itself does not authenticate or persist those structs.
