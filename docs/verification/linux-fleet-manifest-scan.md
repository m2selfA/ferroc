# Linux local manifest scan / dry-run candidate

Linux now implements the existing LOCAL read-only `Runtime::scan_fleet_manifest` and `fleet-dir scan/dry-run`. It adds no network message, MCP tool, approval, signing, journal mutation, apply, replacement, deletion or service. Empty directories are observed, not created or synchronized.

## Native contract

- Reuses Policy and registry→fs_gate/lifecycle. An absolute trusted root and original ancestors are checked. `O_PATH | O_NOFOLLOW` plus `openat` pins components before object validation; FIFOs/devices/symlinks and multi-link regular files are rejected before read IO.
- A validated regular O_PATH FD remains live while procfs reopens that same object for read-only IO. Procfs is required; no pathname fallback. Ordinary source permissions are accepted, unlike private identity/database paths.
- Reads at64KiB, checks cancellation/object/ancestor state around IO, and enforces existing global name/path/depth/hash budgets before queuing. Exact-subtree exclusion skips content IO while enumerated names still count. Initial/final directory names and file size/mtime/ctime are compared.
- Linux retained FDs **do not prevent ancestor rename**. The checks do not create an immutable snapshot or Policy sandbox. The result remains `ReadSequence` / `ExactUtf8Unqualified`; it does not prove current bytes or Windows target-name qualification. Read access may affect atime.
- Existing owner-bound pagination and final NDJSON complete/record-count/SHA contract is reused. A failed or truncated stream is not an empty directory or approved transfer plan.

Primary syscall evidence: [open(2), O_PATH](https://man7.org/linux/man-pages/man2/open.2.html). The source comment and tests deliberately validate pinned symlinks/special objects instead of assuming NOFOLLOW with O_PATH alone rejects every object.
